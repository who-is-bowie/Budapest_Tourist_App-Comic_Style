# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running

No build step, bundler, linter or tests: plain ES modules served statically.

```bash
python3 scripts/serve.py 5173      # static server with Cache-Control: no-store; then open http://localhost:5173
```

- `.claude/launch.json` defines the `budapest-tour` preview server (same command, port 5173). If the port is taken, an earlier server is probably still running and already serves the current files.
- Needs internet at runtime: MapLibre (unpkg), the map style/tiles (`tiles.openfreemap.org`), Three.js (jsdelivr, via the import map in `index.html`) and the walking router (`routing.openstreetmap.de`, falls back to straight-line estimates).
- Deep link `?view=<place-id>` opens that landmark's 3D viewer on load.
- The browser pane can keep a stale ES module in a tab after edits; open a fresh tab if an old error persists.
- `scripts/*.py` are one-off data builders (Overpass → `src/data/*.json`; `build_area.py` needs `shapely`). The JSON is committed; don't re-run them casually. `fetch_photos.py` only fetches landmarks that have no photo yet (`--refresh` for all). `footprint.py way|relation <id>` measures a landmark's real footprint (centre, length, width, long-axis bearing) from the OSM API for its pin and `PLACEMENT`; Overpass mirrors are often overloaded, the OSM API and Nominatim are the reliable fallbacks.

## Architecture

Vanilla JS, no framework. `src/main.js` is the composition root: it loads data, builds the `actions` object (all user intents), wires the menu, map and card, and reacts to store changes.

- **State** (`src/state/store.js`): a single mutable `state` plus `set(patch)` / `subscribe(fn)`. Listeners receive the patch, and `main.js` inspects patch keys to decide what to re-render (menu, card, map, route). Only `stops` and `preset` persist to `localStorage`.
- **Data** (`src/data/places.js`): `loadData()` merges curated `landmarks.json` with bulk `pois.json`, drops anything outside the visible area (`area.json`: districts I, V, VI, VII, VIII, IX, XI plus a City Park box for Heroes' Square / Vajdahunyad / Széchenyi; point-in-polygon `inArea`), and de-dupes POIs against landmarks (a POI is dropped when it shares a distinctive name word with a curated stop within 80 m, or is the same category within 20 m). Curated pins are real OSM positions: building footprint centres for landmarks with models, the feature itself otherwise. Gül Baba's Tomb is in District II, so it is in the data but filtered out of the app. There is no shaded-out mask any more; the map is limited by `BOUNDS` in `mapView.js`. `CATS` defines the five categories. Presets (`presets.json`) are filtered to stops that survived.
- **Map** (`src/map/mapView.js`): MapLibre GL over the OpenFreeMap `liberty` style, which is restyled at load by `funStyle()` into a print-comic look (flat CMY colours, black ink casings and outlines, hard `style.light`, an offset ink shadow under buildings; layer-id based rules). `styles.css`'s `#map-wrap::before/::after` add halftone dots and newsprint grain on top. Real relief is currently switched off (`TERRAIN = false` at the top of `mapView.js`; set it to `true` to bring back the hills, hillshade and landmark terraces). When on, it comes from `addTerrain()`: AWS Terrarium DEM tiles (`s3.amazonaws.com/elevation-tiles-prod`, needs internet) feed `map.setTerrain` (`TERRAIN_EXAGGERATION`) and a `hillshade` layer under the water/roads. Fill, line, circle, symbol and extrusion layers are draped automatically; the Three.js custom layer is not, so `models3d.js` adds `map.queryTerrainElevation` (already exaggerated, relative to `transform.elevation`) to each model's mercator z. On slopes `fitToSlope` also samples the DEM under each model's footprint, rests the model on the 70th-percentile height and builds a `buildFoundation` terrace (stone face with a lawn top whose foot follows the ground; `PLACEMENT.foundation` can be `false` or `'round'`). MapLibre 4.7 drops the camera's look-at elevation on flyTo/easeTo, so `createMap` passes a `transformCameraUpdate` that re-reads it from the DEM (clamped to the DEM's maxzoom). Our own layers (route, pins with ink outlines, caption-box labels from `addCaptionImages`, selected-building extrusions) are added in `addLayers`. Zoom-based radii must be top-level `interpolate` expressions, so ink outlines use the `radius()` helper rather than `['+', zoomExpr, n]`. Selected places get their real building footprint extruded in colour, found via `querySourceFeatures` and cached (`footprints`); places with a 3D model skip this.
- **3D landmarks, two surfaces sharing one set of models:**
  - `src/model3d/kit.js`: the modelling kit. Materials are cel-shaded (`MeshToonMaterial` with a 3-step ramp; `mat()` ignores roughness/metalness) with stone coursing and halftone dots injected by a shared `onBeforeCompile` patch; `zsolnay()` / `banded()` are patterned materials whose UVs are in model units (`unitUVs`), so tiles keep one scale on any part. A builder draws through `k = kit(group)`: primitives (`box`, `cyl`, `lathe`, `dome`, `hip` / `mansard` / `pyramid` roofs, `gable`, `arcade` walls with openings, `pinnacle`, `column`, `balustrade`, `statue`, `rider`, `tree`...) are batched into one merged mesh per material on `k.done()`; `k.at(x, y, z, ry)` gives a child frame, `k.g` the ground frame. Windows (`windows`, `panes`, `ring`; kinds arch / pointed / rect / round, optional framed surround) are instanced and lit. `inked()` builds one inverted-hull ink outline whose line weight follows each part's size (`ink: 'fine'` or `false` per primitive).
  - `src/model3d/buildings.js` and `bridges.js`: the procedural builders (no asset files), proportioned from the real buildings (OSM footprints, published heights; bridges other than the Chain Bridge use compact units with heights stretched ~1.8x). `src/model3d/models.js` maps place ids to builders (`BUILDERS`) and has `buildModel` and the terrace `buildFoundation`. Ground pieces (plazas, hills, water) sit below y=0 and go through `k.g`; `buildModel(id, { base: false })` drops them for the map, the viewer keeps them. `span` in `PLACEMENT` is therefore the structure's size without its base. Convention: units ≈ metres/4, front faces +z, base on y=0 (the viewer's build-up is a rising clip plane, so draw order does not matter). Window materials from `lit()` are returned as `glows` so day/dusk/night can drive emissive intensity. `userData.tick` is an optional per-frame hook (water; `tickIsGround` drops it on the map).
  - `src/model3d/registry.js`: `MODELS` (title, facts, accent) and `PLACEMENT` (real-world `span` in metres = the OSM footprint's long side, compass `facing` of the model's +z; its +x then points to facing − 90°). The model's bbox centre goes on the pin. Real buildings under a model are hidden along a capsule covering its own footprint (`footprints()` in `models3d.js`, a `['distance', LineString]` filter); an explicit `hole` (m) hides a circle instead, used for the bridges. Models include Heroes' Square (`heroes-square`, front faces Andrássy Avenue), Vajdahunyad Castle and Széchenyi Baths. All six Danube road bridges inside the map (Chain, Elizabeth, Liberty, Margaret, Petőfi, Rákóczi) have models; a bridge's `facing` is the real Buda→Pest bearing + 90° (its deck runs along model x), and `shift` ([east, north] metres) moves a model off its pin, used for Margaret Bridge whose bend lies outside the visible districts, so its pin has to sit mid-span instead. Adding a landmark means a builder in `buildings.js` / `bridges.js`, an entry in `BUILDERS` and in both registry tables; the id must match a place id.
  - `src/model3d/viewer.js`: modal diorama viewer (own renderer, orbit controls, day/dusk/night). Opening a model plays a 5.6 s build-up: a clipping plane rises through it with a glowing scan ring while the camera orbits in. Lazy-loaded from `actions.open3D`, so Three.js is not fetched until first use. Its DOM lives in `index.html` (`#viewer`).
  - `src/map/models3d.js`: a MapLibre `custom` layer that renders the same models directly into the map's GL context at each landmark's coordinates (also lazy-loaded from `mapView.loadLandmarks`). It applies the Mercator transform per model, does its own circle hit-testing for clicks, and `mapView.applyHoles()` hides the real buildings underneath with `['distance', …]` filters on `building` / `building-3d`.
- **UI** (`src/ui/menu.js`, `src/ui/card.js`): imperative DOM rendering through the `el()` helper in `src/util.js`; no templates. The menu re-renders wholesale on store changes.
  - The sidebar and card share the map's print-comic look (cream paper, 2.5px ink outlines, hard offset shadows, Lilita One from Google Fonts for lettering). There is no automatic dark mode (no `prefers-color-scheme`); the only dark look is the opt-in night mode below.
  - `src/ui/art.js` draws the place pictures: inline-SVG `GLYPHS` (cocktail, beer, coffee, bread, bridge...) picked by `glyphFor(place)` from category, kind/cuisine detail and name, wrapped by `sticker(place)` on a halftone tile. Landmarks show their Wikipedia photo (`src/data/photos.json`, built once by `scripts/fetch_photos.py`; Wikimedia only serves widths 120/250/330/500/960, so go through `photoAt`) with the glyph as a corner stamp. `rating(place)` renders the review badge and returns `null` when there is no score.
  - Review scores are optional data: `src/data/ratings.json` is `{ "<place id>": { "rating": 4.5, "reviews": 1234 } }`, merged in `loadData()`. It ships empty (`{}`), so no stars show until it is filled; OSM has no ratings and none are invented. Fill it with `GOOGLE_PLACES_API_KEY=... python3 scripts/fetch_ratings.py` (Places API New Text Search; resumable, `--dry-run` / `--limit N` / `--refresh`). The sidebar shows a "Ratings: Google" credit once any score exists, as Google's terms require. Opening the app with `?demo=ratings` loads `src/data/ratings.demo.json` instead (invented sample scores from `scripts/make_demo_ratings.py`, deterministic per place id) and relabels the credit and tooltips as samples, so the badges can be tried without a key; never copy that file into `ratings.json`.
- **Night mode** (the 🌙 fab, `setupNight` in `main.js`): a neon take on the comic look, saved in `localStorage` (`budapest-tour-night`) and applied to `<html data-theme="night">` before first paint by an inline script in `index.html`. `mapView.js` keeps two palettes in `THEMES`; `funStyle(style, palette)` builds either from the untouched `rawStyle`, and `setNight()` diffs the new build against `appliedStyle` (`restyle()`) so colours fade in place, then `applyOwn()` recolours our own layers (pins, route, caption images `caption-night` / `caption-sel-night`). Night-only layers (`road-glow`, `water-glow`, `building-ink-plate`, `places-glow`, `route-glow`) exist in both themes and are hidden or at opacity 0 by day. `models3d.js` eases its lights between the sun and a magenta key / cyan rim with lit windows (`setNight`), and the 3D viewer opens in its night mood. `styles.css` splits `--ink` into `--text` / `--edge` / `--sh` (plus `--field`, `--hover`, ...) so the `:root[data-theme="night"]` block at the end can recolour the UI; keep new borders on `var(--edge)` and offset shadows on `var(--sh)`. The `#zap` wipe on toggle is skipped for `prefers-reduced-motion`.
- **Routing** (`src/routing/walk.js`): per-leg foot routing with a cache and an estimate fallback; `suggest/suggest.js` ranks nearby places for the card.

## Gotchas

- `[hidden]` is forced to `display: none !important` in `styles.css`; without it, components that set `display` (the fixed full-screen `#viewer`) stay on screen invisibly and swallow map clicks.
- Style validation errors in `funStyle` (e.g. setting `line-color` on a symbol layer) make the whole map fail to load silently apart from a `map error:` console line.
- Mobile layout (≤760px) turns the sidebar into a bottom sheet (`data-sheet` = peek/half/full, driven in `setupChrome` in `main.js`); the map must be `resize()`d after height changes.
